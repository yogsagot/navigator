# Navigator でのコピーと貼り付け

端末プログラムの中でのコピーと貼り付けは、見た目ほど単純ではありません。Navigator は自分のウィンドウを持たないので、グラフィカルなエディターのようにデスクトップのクリップボードと直接やり取りすることができません。クリップボードに届く方法は二つあります：

- **小さなクリップボードツール** をコンピューターにインストールする方法 (X11 なら `xclip` か `xsel`、Wayland なら `wl-clipboard`)。Navigator がテキストをツールに渡し、ツールがそれをクリップボードに置きます。こちらが確実な方法です。
- **端末。** Navigator は、端末にテキストをクリップボードへ置くよう、あるいはクリップボードから読み返すよう頼むことができます。これに応じる端末もあれば、先に確認してくる端末も、頼みをまったく無視する端末もあります。

さらに、端末はいくつかのキーを自分用に取っておくので、ある端末でコピーできるキーが、別の端末では Navigator まで届かないことがあります。このガイドでは、どこで何が動くのか、そしてすべてがそのまま動くように設定する方法を説明します。

## クイックスタート

1. **クリップボードツールをインストールします。** まず、どの種類のデスクトップセッションを使っているかを調べます：

   ```sh
   echo $XDG_SESSION_TYPE
   ```

   次に、それに合ったツールをインストールします：

   | セッション | Debian、Ubuntu、Mint | Fedora |
   |-----------|-------------------------------|--------------------------------|
   | `x11`     | `sudo apt install xclip`      | `sudo dnf install xclip`       |
   | `wayland` | `sudo apt install wl-clipboard` | `sudo dnf install wl-clipboard` |

   `xsel` も `xclip` と同じように使えます。どちらか一つあれば十分です。

2. **エディターでは Ctrl+C、Ctrl+X、Ctrl+V を使います。** これまでに試したすべての端末で動作します。

3. **Ghostty を使っている場合は**、次の行を `~/.config/ghostty/config` (または `config.ghostty`) に追加して Ghostty を再起動します：

   ```
   keybind = ctrl+insert=unbind
   keybind = shift+insert=unbind
   ```

たいていの人に必要なのはこれだけです。このガイドの残りは、その背後にある詳細です。サーバー上で ssh 経由で Navigator を動かしている場合は、[ssh 経由のリモートサーバーで](#ssh-経由のリモートサーバーで)を参照してください。

## キー

キーは、Navigator のどこにいるかによって異なります。

### エディター (F4)

| 操作 | キー |
|--------------------------------------------|-------------------------------------|
| コピー | **Ctrl+C**、Ctrl+Ins または Ctrl+Alt+C |
| 切り取り | **Ctrl+X**、Shift+Del または Ctrl+Alt+X |
| 貼り付け | **Ctrl+V**、Shift+Ins または Ctrl+Alt+V |
| 選択したブロックをコピーせずに削除 | Ctrl+Del |

この四つは **エディタ** メニュー (エディターがアクティブな間メニューバーにあります) の先頭にもあります。

コピーと切り取りは、選択したブロックに対して働きます。ブロックを選択するには、Shift を押しながらカーソルを動かすか、マウスでドラッグします。

キーが三組あるのは、どこでも動く一組がないからです：

- **Ctrl+Ins / Shift+Del / Shift+Ins** は DOS Navigator 本来のキーです。端末によっては Ctrl+Ins と Shift+Ins を自分用に取っておきます ([端末ごとの注意](#端末ごとの注意)を参照)。
- **Ctrl+C / Ctrl+X / Ctrl+V** は、ほかのどのプログラムも使うキーです。
- **Ctrl+Alt+C / Ctrl+Alt+X / Ctrl+Alt+V** は、端末やデスクトップがほかの二組を取ってしまう場合のための予備です。

> **DOS Navigator から来た方へ。** DOS Navigator のエディターは、Ctrl+C、Ctrl+X、Ctrl+V を Page Down、カーソルを下へ、挿入/上書きの切り替えに使っていました (WordStar のキー)。Navigator はこれらを代わりにクリップボードに使います。PgDn、Down、Ins は今もその役目を果たします。ほかの WordStar のキー (Ctrl+K…、Ctrl+Q…、Ctrl+E、Ctrl+S など) も既定では割り当てられていません。設定 > 構成 > キー割り当て > 読込 から `keybindings_wordstar.ini` を読み込むとそれらが戻り、`keybindings_dn151.ini` を読み込むと DN の Ctrl+C/X/V も戻ります。

### ダイアログの入力行とコマンドライン

| 操作 | キー |
|-------|------------------------------------------------------------------------------------------------------|
| コピー | Ctrl+Ins：選択範囲を、何も選択していなければ行全体をコピーします。Ctrl+C は選択範囲をコピーします。 |
| 切り取り | Shift+Del |
| 貼り付け | Shift+Ins または Ctrl+V |

行の中でテキストを選択するには、Shift を押しながらカーソルを動かすか、マウスでドラッグします。

パネルの下のコマンドラインでは、**Ctrl+E と Ctrl+X はコマンド履歴を前後にたどる** ので、そこでは Ctrl+X で切り取りはできません。

### コンソール (Ctrl+O)

マウスでドラッグしてテキストを選択するか、単語をダブルクリックします。それから：

| 操作 | キー |
|-------|-------------------------------------------------------------------------|
| コピー | Ctrl+Ins、またはプログラムが実行されていなければ Ctrl+C |
| 貼り付け | 端末自身の貼り付けキー (たいていは Ctrl+Shift+V)、または中クリック |

コンソールでプログラムが実行されているときは、予想どおり Ctrl+C はそのプログラムに送られます (たいていは停止させます)。貼り付けたテキストも、実行中のプログラムに送られます。

### その他のコピー方法

- **電卓**：*コピー* ボタン (Classic) と *電卓 > コピー* (すべての表示形式) は、結果をクリップボードに置きます。
- **画面キャプチャ** (Alt+Shift+Ins)：矢印キーと Shift+矢印キーで範囲を移動・サイズ変更し、Enter を押すと画面のその部分がテキストとしてコピーされます。あるいはマウスで範囲をドラッグすると、ボタンを離したときにコピーされます。Esc または右クリックで、コピーせずに抜けます。
- **列の合計** (エディターで Alt+Ins、矩形ブロックがオンのとき)：選択した列の数値を合計し、その合計をクリップボードに置きます。

## マウスとプライマリセレクション

Linux には、実はクリップボードが二つあります：

- **クリップボード**。コピーで書き込まれ、貼り付けで読み出されます。
- **プライマリセレクション**。テキストを選択するだけで書き込まれ、マウスの中ボタンで貼り付けられます。

Navigator も同じ慣習に従います。エディター、コンソール、入力行でテキストの上をドラッグすると、それがプライマリセレクションになり、**中クリック** でプライマリセレクションが貼り付けられます。**ダブルクリック** は単語を選択します。

Navigator はマウスを自分で使うので、Navigator の実行中は端末自身のマウスによる選択は使えません。それでも使いたいとき (端末のやり方でテキストを選択したいときや、端末の右クリックメニューを開きたいとき) は、**Shift を押しながら** ドラッグやクリックをします。たいていの端末で使えます。

## 端末自身の貼り付け

端末には独自の貼り付けキー (たいていは **Ctrl+Shift+V**) と、メニューの貼り付け項目があります。この貼り付けは端末が行います：デスクトップのクリップボードの内容を、あなたが入力したかのように Navigator に打ち込みます。Navigator の設定がどうであれ、クリップボードツールがインストールされていてもいなくても動きます。

ほかのプログラムでコピーしたテキストの貼り付けはうまくいくのに、Navigator *から* のコピーはうまくいかない、ということがあるのはこのためです：前者の向きは端末の仕事で、後者は Navigator の仕事です。

## 「システムのクリップボード」設定

**設定 > 構成 > システム設定 > システムのクリップボード**

- **オン** (既定)：コピーするとテキストがデスクトップのクリップボードに置かれ、ほかのプログラムで貼り付けられます。貼り付けはデスクトップのクリップボードを読みます。
- **オフ**：DOS Navigator と同じように、Navigator は独自の非公開のクリップボードを持ちます。コピーしたものが Navigator の外へ出ることはありません。端末自身の貼り付け (Ctrl+Shift+V) では、今もデスクトップのクリップボードの内容を取り込めます。

この設定がどちらであっても、Navigator は最後にコピーしたものの写しを常に自分でも保持します。

## 端末ごとの注意

端末によっては、Navigator に届く前にキーを自分用に取ってしまいます。また、プログラムにクリップボードを使わせるかどうかも端末によって異なります。

| 端末 | 自分用に取るキー | Navigator にクリップボードを使わせるか | 対処 |
|-------------------------------------------|-----------------------------------------------|----------------------------------|------------------------------------------|
| **Ghostty** | Ctrl+Ins、Shift+Ins、Shift+PgUp/PgDn/Home/End | コピー：はい。貼り付け：先に確認する | キーの割り当てを解除する (下記) |
| **xfce4-terminal、GNOME Terminal、Tilix** | Ctrl+Ins、Shift+Ins (変更できない) | いいえ | クリップボードツールをインストールし、Ctrl+C/X/V を使う |
| **PyCharm などの JetBrains の端末** | – | いいえ | クリップボードツールをインストールする |

### Ghostty

Ghostty は既定で、**Ctrl+Ins** を自身の選択範囲のコピーに、**Shift+Ins** をプライマリセレクションの貼り付けに使うので、これらのキーは Navigator に届きません。また、Shift+PgUp、Shift+PgDn、Shift+Home、Shift+End をスクロールに使いますが、エディターはこれらをテキストの選択に必要とします。次の内容を Ghostty の設定ファイルに追加して、Ghostty を再起動してください (すべてのウィンドウを閉じます。新しいタブを開くだけでは不十分です)：

```
keybind = ctrl+insert=unbind
keybind = shift+insert=unbind
keybind = shift+page_up=unbind
keybind = shift+page_down=unbind
keybind = shift+home=unbind
keybind = shift+end=unbind
```

Ghostty 自体では、引き続き Ctrl+Shift+C と Ctrl+Shift+V でコピーと貼り付けができます。

Ghostty は、プログラムがクリップボードを *読む* 前に許可を求めます。クリップボードツールがインストールされていなければ、Navigator はあなたの返事を待たずに、自分が最後にコピーしたものを貼り付けます。確認なしで Navigator にクリップボードを読ませるには、次を追加します：

```
clipboard-read = allow
```

Ghostty がどのキーを割り当てているかを見るには、`ghostty +list-keybinds --default` を実行します。

### xfce4-terminal、GNOME Terminal、Tilix

これらの端末はどれも同じライブラリ (VTE) の上に作られていて、**Ctrl+Ins** (コピー) と **Shift+Ins** (プライマリセレクションの貼り付け) をライブラリ自身が処理します。これらのキーを返してもらう設定はないので、代わりに **Ctrl+C / Ctrl+X / Ctrl+V** (または Ctrl+Alt+C / X / V) を使ってください。

これらの端末は、クリップボードを使いたいというプログラムの要求も無視するので、Navigator からコピーして外へ出すには **クリップボードツールが必要** です。

**xfce4-terminal** では、*Edit > Preferences > Advanced* も開いて、**Disable all menu access keys** と **Disable menu shortcut key** をオンにしてください。そうしないと、Navigator が使う Alt+E、Alt+F、Alt+V、Alt+T、Alt+B、Alt+H、F10 で端末が自分のメニューを開いてしまいます。クリップボードとは関係ありませんが、次にぶつかる問題です。

### PyCharm などの JetBrains の IDE

組み込みの端末は、クリップボードを使いたいというプログラムの要求を無視するので、クリップボードツールをインストールしてください。*システムのクリップボード* をオフにすれば、Navigator の中でのコピーと貼り付けはツールなしで動きます。

## クリップボードツールがない場合

クリップボードツールがインストールされていなくても、Navigator は動きます：

- **Navigator の中** でのコピーと貼り付けは動きます。デスクトップのクリップボードを読めないときは、Navigator は自分が最後にコピーしたものを貼り付けます。初めてそうなったときに、クリップボードツールのインストールを勧めるメッセージが表示されます。
- **Navigator から** ほかのプログラムへのコピーは、端末が要求を受け入れる場合にだけ動きます (Ghostty は受け入れ、xfce4-terminal、GNOME Terminal、PyCharm は受け入れません)。
- ほかのプログラムから **Navigator へ** の貼り付けは、端末自身の貼り付けキー (Ctrl+Shift+V) で常に動きます。

注意すべきなのは、その場合 Navigator の貼り付けが、その後にほかのプログラムでコピーしたものではなく、*Navigator で最後にコピーしたもの* を貼り付けることがある点です。

## ssh 経由のリモートサーバーで

ssh 経由で別のマシン上の Navigator を動かすとき、Navigator は *そちら* で動いていますが、使いたいクリップボードは *あなたの* コンピューターにあります。サーバー上のクリップボードツールだけでは役に立ちません：サーバーにはデスクトップがないので、そこの `xclip` にはテキストの置き場所がないのです。この溝を埋める方法は三つあり、複数を併用することもできます。

**Navigator の中でのコピーと貼り付けは、何を設定しても常に動きます。** あなたのコンピューターのクリップボードに届かないときは、Navigator は自分が最後にコピーしたものを貼り付けます。

### 取り込む: 端末の貼り付けキー

端末自身の貼り付け (たいていは **Ctrl+Shift+V**、またはそのメニュー) は、ローカルのクリップボードの内容を ssh セッションに打ち込みます。設定は不要で、取りに戻る必要がないので、コンピューターからテキストを取り込む最も速い方法です。Navigator 自身の貼り付けキーが必要なのは、Navigator の中でコピーしたテキストの場合だけです。

### 外へ出す: 端末 (OSC 52)

Navigator は、OSC 52 という端末の機能を使って、コピーしたテキストをクリップボードに置くようローカルの端末に頼みます。この要求はほかの出力と同じように ssh 接続を流れていくので、サーバー側には何も必要ありません。動くかどうかは **ローカルの** 端末によります：

| 端末 | 外へのコピー |
|-------------------------------------------|--------------------------------------------------|
| Ghostty、WezTerm、foot | 動く |
| kitty | 動く (`clipboard_control` が `write-clipboard` を許可している必要がある。既定では許可されている) |
| Alacritty | 動く (`[terminal]` の `osc52` が `Disabled` でない必要がある) |
| xfce4-terminal、GNOME Terminal、Tilix | 非対応。X11 転送を使う (下記) |
| PyCharm などの JetBrains の端末 | 非対応 |

Navigator を使わずに端末を試すには、サーバーで次を実行し、それからコンピューターで貼り付けます：

```sh
printf '\e]52;c;%s\a' "$(printf hello | base64)"
```

`hello` が届けば、Navigator からのコピーも動きます。届かなければ、その端末は OSC 52 を無視しています。

OSC 52 はクリップボードを *読む* こともできますが、たいていの端末は拒否するか先に確認してくるので、取り込むには端末の貼り付けキーを使ってください。

### 両方向: X11 転送

ssh は、サーバーからあなたのコンピューターへ X11 の接続を運ぶことができます。するとサーバーはあなたのデスクトップにつながる `DISPLAY` を得て、サーバー上の Navigator のクリップボードツールが **あなたの** クリップボードに届きます。端末が何に対応しているかにかかわらず、コピーにも貼り付けにも使えます。

必要なもの：

- **あなたのコンピューターに**：X サーバー。X11 のデスクトップならどれにもあります。Wayland では XWayland がその役目を果たし、クリップボードを Wayland のプログラムと共有します。
- **サーバーに**：`xclip` (または `xsel`) と `xauth` (`sudo apt install xclip xauth`、または `sudo dnf install xclip xorg-x11-xauth`)、そして `/etc/ssh/sshd_config` の `X11Forwarding yes` (たいていのディストリビューションでは設定済みです)。`sudo sshd -T | grep -i x11forwarding` で確認できます。

それから **`-Y`** を付けて接続します：

```sh
ssh -Y user@server
```

初回は `/usr/bin/xauth: file /home/user/.Xauthority does not exist` と表示されることがあります。これは無害です：`xauth` がファイルを作り、このメッセージは二度と出ません。動いているか確認するには：

```sh
echo $DISPLAY                            # localhost:10.0 のような値
echo hello | xclip -selection clipboard  # それからコンピューターで貼り付ける
```

その同じセッションから、*システムのクリップボード* をオンにして Navigator を起動します。そのサーバーに接続するたびに X11 を転送するには、あなたのコンピューターの `~/.ssh/config` に次を追加します：

```
Host server
    ForwardX11 yes
    ForwardX11Trusted yes
```

知っておくべきこと：

- **セキュリティ。** `-Y` は、あなたの X セッションをサーバーに委ねます：接続している間、サーバー上のプログラムや、そこで root 権限を持つ誰もが、あなたのキー入力、画面、クリップボードを読めます。信頼できるサーバーでだけ使ってください。単なる `-X` はサーバーを制限しますが、その制限によって `xclip` がクリップボードを読めなくなることもあり、貼り付けが動かない場合があります。
- **貼り付けには少し遅れがあります。** Navigator で貼り付けるたびにサーバー上で `xclip` が起動し、ネットワーク越しにあなたのクリップボードを取ってきます。インターネット越しなら数百ミリ秒は普通です。端末の貼り付けキーなら、この往復が要りません。取得に 2 秒より長くかかると、Navigator はあきらめて自分が最後にコピーしたものを貼り付けます。
- **切断するとコピーが消えることがあります。** コピーしたテキストは `xclip` がサーバーから提供し続けているので、ログアウト後も必要なら、ログアウトする前にコンピューターのどこかに貼り付けておいてください。

### tmux や screen の中で

**tmux** の中では、`~/.tmux.conf` に次を追加して、tmux が OSC 52 のコピー要求を端末に渡すようにします：

```
set -g set-clipboard on
```

X11 転送は、tmux のセッションが転送ありの ssh セッションから開始されていれば、tmux の中でも動きます。それより前に作られたセッションや、新しい接続から再アタッチしたセッションは、古い `DISPLAY` を保持しています。そこで新しい値で `export DISPLAY=...` を実行するか、新しい tmux のウィンドウで Navigator を起動してください。

コピーしたときに端末がゴミを表示する場合は、Navigator を `NAVKIT_CLIPBOARD=off nav` で起動して、端末経由の方法をオフにできます。

## トラブルシューティング

**コピーしても何も起きない、またはテキストがほかのプログラムに届かない。**
クリップボードツールがインストールされておらず、端末が Navigator の要求を無視しています。`xclip` か `wl-clipboard` をインストールしてください ([クイックスタート](#クイックスタート)を参照)。

**貼り付けると、ほかのプログラムで今コピーしたものではなく、古いテキストが貼り付けられる。**
Navigator がデスクトップのクリップボードを読めず、自分が最後にコピーしたものを使いました。クリップボードツールをインストールしてください。Ghostty では `clipboard-read = allow` を設定することもできます。それまでは、端末の貼り付けキー (Ctrl+Shift+V) を使ってください。

**Shift+Ins で貼り付けられるものが Ctrl+V と違う。**
端末が Shift+Ins を捕まえて、クリップボードではなく *プライマリセレクション* (どこかで最後に強調表示したテキスト) を貼り付けました。Ghostty では、上で示したように割り当てを解除してください。xfce4-terminal と GNOME Terminal では Ctrl+V を使ってください。

**キーを押してもまったく何も起きない。**
おそらく端末かデスクトップがそのキーを取っています。Navigator のソースをチェックアウトしてあれば、実際に何が届いているかを確認できます：

```sh
./venv/bin/python tools/keyprobe.py
```

キーを押します。何も表示されなければ、端末がそのキーを取っています。`q` を二回押すと終了します。上に挙げたほかのキーを使うか、自分で割り当ててください (次のセクション)。

**ssh 経由だと、コピーしたテキストがコンピューターに届かない。**
サーバーにはデスクトップがなく、ローカルの端末が OSC 52 を無視しています。X11 転送 (`ssh -Y`) を使うか、OSC 52 に対応した端末を使ってください。[ssh 経由のリモートサーバーで](#ssh-経由のリモートサーバーで)を参照してください。

**ssh 経由だと、貼り付けに少し時間がかかる。**
X11 転送では、貼り付けるたびにネットワーク越しにクリップボードを取ってきます。コンピューターからのテキストには、端末の貼り付けキー (Ctrl+Shift+V) を使ってください。往復が要りません。

**ある端末では動くのに、別の端末では動かない。**
それは想定どおりです。[端末ごとの注意](#端末ごとの注意)でその端末を確認してください。

## キーの変更

どのキーも、**設定 > 構成 > キー割り当て** または `~/.config/navigator/keybindings.ini` で自由に変更できます。一つのコマンドに、カンマで区切って複数のキーを割り当てられます：

```ini
clipboard_cut = shift+delete, ctrl+x, ctrl+alt+x
clipboard_copy = ctrl+insert, ctrl+c, ctrl+alt+c
clipboard_paste = shift+insert, ctrl+v, ctrl+alt+v
```

同じ場所では、一つのキーは一つのコマンドにしか属せません。エディターで Ctrl+C をほかの用途に割り当てるには、まず `clipboard_copy` から外してください。

Navigator は最初の起動時に、すべての既定値を書き込んだファイルを作り、そこに書かれた内容を保持します。ファイルが既定値の変更より古い場合は、古いキーのままです。キー割り当てダイアログでコマンドを選び、**既定** を押すと新しいキーになります。
